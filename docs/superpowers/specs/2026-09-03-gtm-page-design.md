## 交付物

### 交付物 1：`gtm/README.md`（新文件，约 150-220 行，中文）

六节结构，自上而下：

1. `## 定位`
   - 求职线一句话：把具身智能研究组织成可复现、可讲解语料库的独立研究项目；卖点是研究组织力与诚实标注（待核实、设计文档状态透明）。
   - 社区线一句话：中文最系统的具身智能研究语料库 + Demo 场景工作台；卖点是可检索、互链、统一模板。
2. `## 时机判断`（页面核心，回应"按 GTM 最佳时间"）
   - 双线分档依据，各 2-4 句：
     - 求职线现在可用：P0 可信度问题已修复（硬件/概念/方法笔记参考节补齐、死链清理、状态矛盾消除，见 2026-09-02 前后提交）；语料 + 场景定义足以展示研究组织能力；定位诚实——设计文档就明说是设计文档。
     - 社区线等 M3：开源第一印象只有一次；"0 行代码"在大流量渠道易被定性为 PPT 项目；首个可跑复现（M3）是最小可信度证明。
   - 时机表（4 行 × 3 列）：阶段（现在 2026-09 / M2 收尾 / M3 落地 / M4 完成）× 该做什么 × 面向谁。
   - 反模式警示一段：门禁未过不投大流量渠道——开源社区的一次性印象成本不可逆。
3. `## 可信度门禁`（社区公开推广前置条件，Markdown 任务清单逐项可勾）
   - [ ] 场景 01 达成最小可跑复现（以 `docs/roadmap.md` M3 定义为准）
   - [ ] README 数字与仓库实际一致
   - [ ] 全部笔记有参考节且无死链
   - [ ] 时间线"待核实"条目已核实或移除
   - [ ] `demo/assets` 至少 1 个真实素材（图或视频）
   - [ ] LICENSE 与引用方式明确
4. `## 渠道与动作`
   - 求职线（现在激活）：简历项目栏话术（一句话 + 仓库链接 + 状态标签）；面试 STAR 要点（为什么做 / 怎么组织 / 取舍是什么，诚实标注是加分项）；猎头与内部转岗一页纸引用本页定位。
   - 社区线（门禁通过后激活）：渠道清单（掘金 / V2EX / 知乎 / LeRobot Discord 等，附各自适配的内容形态）；发布物要点（首发帖结构）；凡涉及"发布时间窗口"类经验断言，一律标注"（经验推测，待核实）"。
5. `## 里程碑触发器`（表格 3 行 × 2 列：M2 收尾 / M3 落地 / M4 完成 × 触发的 GTM 动作）
6. `## 元信息`
   - 状态行 + 最后更新日期（2026-09-03）+ 声明：进度事实源是 `docs/roadmap.md`，本页不复制进度数字。

## 内容原则

1. **引用不复制**：篇数、进度等动态数字只链接到 `docs/roadmap.md` / 根 README 对应锚点，不抄写数字，防止出现第三处状态事实源。
2. **诚实文化**：无来源断言一律标注（经验推测，待核实），与仓库现有"待核实"标注体例一致。
3. **落笔前核实**：实施第一步先核实"P0 已修复"表述与仓库现状一致（参考节存在性、死链、状态数字），若有出入，按现状表述，不写未验证的声明。
4. **遵循 `docs/conventions.md`**：GFM、标题不跳级、中文标题、目录名英文连字符。

## 验收标准

- `gtm/README.md` 六节齐全，无 TBD / 占位符 / 半成品表述。
- 文中所有仓库内相对链接指向的文件存在。
- 根 README 知识地图含 gtm/ 行，树形符号（├──/└──）连贯。
- 页面自身不出现独立的状态数字（进度一律链接 roadmap）。
- 表述与 `docs/roadmap.md`、`docs/conventions.md` 一致。

## 范围外（明确不做）

- 不新建 gtm/ 其他子页（timing / channels / checklist 不拆页）。
- 不改 `docs/roadmap.md` 状态（GTM 动作不回写进度）。
- 不执行实际发布动作（简历投放、社区发帖由用户自行执行）。
- 不生成 demo 素材。
