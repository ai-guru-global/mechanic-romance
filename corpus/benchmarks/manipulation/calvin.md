# CALVIN 基准（Composing Actions from Language and Vision）

> **一句话定位**：首个系统评测**长程（long-horizon）、语言条件（language-conditioned）**机器人操作的仿真基准——智能体必须在不重置环境的连续 5 个任务链里，按语言指令依次完成抽屉开合、推块、开灯等操作。Mees et al., RA-L 2022。

> 最后更新：2026-08

---

## 1. 概览与定位

CALVIN 由弗莱堡大学（University of Freiburg）Oier Mees 等人发布于 IEEE RA-L 2022，是具身操作领域**第一个把「长程序列 + 自然语言指令」作为一等评测对象**的公开基准。在它之前，大多数操作基准（如 MetaWorld、RLBench）评测的是**单步、短程**任务；CALVIN 的核心贡献是把评测难度从「完成一个动作」抬升到「在同一个未重置的场景里连续完成 5 个语义不同的任务」。

这恰好对应真实世界的需求：家用机器人很少只做一件事——它要「打开抽屉 → 取出杯子 → 关上抽屉 → 放到桌上 → 推一下瓶」。CALVIN 把这种**多阶段、有依赖、无重置**的设定形式化。

| 属性 | 数值 / 说明 |
| --- | --- |
| 发布年份 | 2022（RA-L） |
| 仿真平台 | **PyBullet**（基于 Bullet 物理引擎） |
| 本体 | Franka Panda 7-DoF 单臂 + 平行夹爪 |
| 任务原语数 | **34 个**基础任务（开/关抽屉、推/拉滑块、开/关灯等） |
| 环境变体 | **4 个**（A / B / C / D），桌面物体布局不同 |
| 语言指令 | 每个任务配套自然语言模板（如 *"open the drawer"*） |
| 观测 | 静态相机 + 腕部相机 RGB（128×128 或 64×64），关节状态 |
| 动作 | 7-DoF 增量（末端 delta pose + 夹爪） |
| 数据 | 每个环境提供大量**无标注**自玩演示（用于预训练） |
| 评测协议 | 5 任务链，不重置，504 条 rollout |

## 2. ABCD 四个环境与评测 Splits

CALVIN 的精髓在于它的**四个环境（A/B/C/D）**。它们共享同一套机器人、同一套任务原语，但**桌面物体的位姿、颜色、空间布局不同**。这设计允许研究者精细地隔离「学没学会任务」与「能不能泛化到新布局」。

### 2.1 四个环境

| 环境 | 说明 |
| --- | --- |
| **A** | 基准布局：抽屉、滑块、灯、色块的某种固定排布 |
| **B** | 物体种类相同，位姿/颜色变化 |
| **C** | 另一组位姿变化 |
| **D** | 第四种布局，常作为 held-out 测试环境 |

四个环境在视觉与空间上**足够相似以共享底层技能**，又**足够不同以考验泛化**。

### 2.2 标准 Splits

论文与排行榜约定了几种训练/测试组合，按「在哪些环境训练、在哪个环境测」命名：

| Split | 训练环境 | 测试环境 | 考验什么 |
| --- | --- | --- | --- |
| **DD** | D | D | 纯模仿能力（同环境） |
| **DB / DC / DA** | D | 其他 | 跨布局泛化 |
| **ABC→D** | A, B, C | D（held-out） | **标准长程泛化设定**（最常用） |
| **ABCD→D** | A, B, C, D | D | 多环境联合训练（上限） |
| **A→B、B→C 等** | 单环境 | 另一环境 | 单源迁移 |

**ABC→D 是事实上的主榜**：模型在 A/B/C 上学，在从未见过的 D 上测 5 任务链。这是 CALVIN 最有区分度的设定——纯记忆型方法会在 D 上崩，只有真正学到「物体-动作-语言」关联的方法才能泛化。

## 3. 任务集与语言条件

### 3.1 任务原语（34 个）

CALVIN 的 34 个基础任务围绕一张固定桌面展开，物体类别有限但组合丰富：

| 物体 | 典型任务 |
| --- | --- |
| **抽屉**（drawer） | 打开抽屉 / 关上抽屉 |
| **滑块**（slider） | 把滑块推到左 / 推到右 |
| **灯**（lightbulb / LED） | 开灯 / 关灯 |
| **色块**（colored block） | 推/放指定色块到目标位置 |
| **转盘**（rotating switch） | 旋转到指定角度 |

每个任务有明确的**成功判定**（基于物体状态，非启发式），并由一条**自然语言指令**触发（如 *"push the red block to the left"*）。

### 3.2 语言条件的两种模式

- **play-with-labels**：数据中每条轨迹段都自动配有语言标签（来自脚本化采集）。
- **unlabeled play**：大量自由交互数据无语言标签，可用于表征预训练。

语言模板由 CALVIN 的任务生成器自动产生，覆盖物体、颜色、方向等组合，规模达数千条变体。

### 3.3 长程链（Task Chain）的核心难点

评测时，智能体拿到**一个有序的 5 任务指令序列**，必须在**同一个连续 rollout** 里完成：

```
指令序列：[打开蓝色抽屉] → [把红色块推到左边] → [关灯] → [拉滑块到右] → [关上抽屉]
环境不重置 → 前一步的状态决定下一步的起点。
```

难点：

1. **状态依赖**：第 3 步能不能做，取决于第 2 步把块推到了哪。
2. **无重置**：错误会沿链累积，一步失败后续可能全废。
3. **长程信用分配**：策略必须知道自己处于链的哪一步、当前该追哪个子目标。

## 4. 评估指标与协议

CALVIN 的评测协议是其最大贡献之一，设计严谨且被后续工作广泛沿用。

### 4.1 指标

| 指标 | 全称 | 定义 |
| --- | --- | --- |
| **AC** | Average number of tasks Completed | 504 条 rollout 中平均完成的任务数（0–5） |
| **Success rate @ k** | — | 至少连续完成 *k* 个任务的比例（k = 1…5） |
| **AR** | Average success Rate | 5 个 success rate@k 的算术平均（综合分） |

主榜通常报 **AC**（平均完成数）和 **5-task chain success rate**（连续完成 5 个的比例）。

### 4.2 评测流程

1. 在 split 指定的环境上训练策略。
2. 在 D 环境上，从 504 个初始状态出发，每个 rollout 给一条 5 任务指令序列。
3. 每完成一个任务，自动切换到下一条指令；若在限定步数内未完成，记该任务失败并停止该 rollout（或继续下一任务，取决于版本）。
4. 统计 AC 与 success@k。

> 504 这个数 = 多个初始状态 × 多条指令序列的组合，保证评测覆盖充分。

## 5. 基线分数参考

下表为公开方法在 **ABC→D** 设定下的代表性分数（不同实现/复现有波动，仅供量级参考；数值随年份持续被刷新）。

| 方法 | 类型 | 年份 | AC（/5） | 5-task 成功率 |
| --- | --- | --- | --- | --- |
| **MCIL** | 经典多任务 IL | 2022 | ~1.6 | ~3% |
| **SuSIE** | 子目标生成 + IL | 2023 | ~2.5 | ~7% |
| **RoboFlamingo** | VLM 条件策略 | 2024 | ~3.4 | ~15% |
| **HULC / HULC++** | 层次化语言条件 | 2022/23 | ~3.9 | ~20% |
| **SuSIE（强设定）** | + 大量预训练 | 2023 | ~4.0 | ~22% |
| **GR-1 / GR-2** | 视频-语言预训练 | 2024 | ~4.2 | ~30% |
| **Long-VLA / π₀ 系** | 长程 VLA | 2024–25 | ~4.5+ | ~40%+ |

> 注：精确数字请查阅 CALVIN 官方 leaderboard（http://calvin.cs.uni-freiburg.de/）。早期基线 MCIL 的 5-task 成功率仅个位数，说明长程任务极难；2024 年后 VLA 类方法才把 5-task 推到 30%+。

### 5.1 为什么分数普遍偏低？

- 5 个任务**全部连续成功**概率 = 各步成功率的乘积。即使每步 80%，5 连也只有 33%。
- 环境不重置 → 误差累积放大。
- D 环境未见过 → 视觉泛化是额外门槛。

## 6. 设计理念与价值

### 6.1 为什么 CALVIN 是里程碑

1. **首次把长程 + 语言条件作为一等公民**。在它之前，操作基准几乎只评单步成功率；CALVIN 强制社区面对「连续多任务」这个真实难题。
2. **泛化设定清晰可隔离**。ABCD 四环境 + 多 split 让「学没学会」和「能不能泛化」可分别度量。
3. **任务定义客观**。成功判定基于物体状态，非人工启发式，可复现。
4. **数据量大且统一**。每个环境提供大量 play 数据，方便预训练/表征学习。
5. **成为长程操作的事实标准**。后续 VLA、世界模型、层次化方法几乎都在 CALVIN 上报分。

### 6.2 它推动的技术方向

- **层次化策略**（hierarchical policy）：高层规划子目标，低层执行。
- **世界模型 / 子目标生成**（如 SuSIE 用扩散模型生成下一帧子目标图像）。
- **VLM 条件化**：用预训练视觉-语言模型理解指令与场景。
- **长程信用分配**与**任务切换检测**。

## 7. 局限

### 7.1 仿真偏简单

CALVIN 基于 **PyBullet**，渲染与物理都偏朴素：

- **物体类别少**：只有抽屉、滑块、灯、色块、转盘等几类，缺乏真实家庭的多样性。
- **视觉真实度低**：128×128 的简易渲染，与现代真机 RGB 差距大，sim-to-real 价值有限。
- **任务动作粗粒度**：主要是开/关、推/拉，没有精细插入、装配、双臂协调。

### 7.2 物体少、场景单一

- 只有一张固定桌面、固定物体集；没有杂乱场景、遮挡、多物体干扰。
- 语言指令模板化，复杂度和真实人类指令有差距（无指代、无否定、无条件）。

### 7.3 其他

- **PyBullet 并行性一般**：大规模 RL 训练效率不如 Isaac。
- **成功判定依赖物体状态**：真机迁移时这些 state 很难精确获取。
- **长程评测方差大**：504 rollout 仍可能有较大统计波动。

### 7.4 与新基准的差距

对比 LIBERO（更精细的泛化维度划分）、RLBench（更精细的单任务设计），CALVIN 的优势在长程、劣势在任务丰富度与视觉真实度。

## 8. 与同类基准对比

| 维度 | **CALVIN** | LIBERO | RLBench | MetaWorld |
| --- | --- | --- | --- | --- |
| 仿真 | PyBullet | robosuite / MuJoCo | CoppeliaSim | MuJoCo |
| 长程评测 | **✅ 5 任务链（核心）** | 部分（Long suite） | ❌ 单任务 | ❌ 单任务 |
| 语言条件 | **✅ 核心** | ✅ | ✅ | ❌ |
| 泛化维度 | 环境布局（ABCD） | 空间/物体/目标 | 任务变体 | 任务 |
| 任务数 | 34 原语 | 130 | 100（PerAct 用 18） | 50 |
| 视觉真实度 | 低 | 中 | 中高 | 低 |
| 主流用途 | 长程 VLA、世界模型 | VLA 泛化评测 | 3D 方法（PerAct） | RL 算法 |
| 发布年 | 2022 | 2023 | 2020 | 2019 |

一句话：**CALVIN 赢在长程，LIBERO 赢在泛化维度，RLBench 赢在任务精细度，MetaWorld 赢在 RL 友好**。
